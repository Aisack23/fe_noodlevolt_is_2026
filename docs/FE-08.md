# FE-08 — Mis pedidos y reseñas

## Rutas y acceso

| Ruta | Uso | Acceso de interfaz |
|---|---|---|
| `/pedidos` | Pedidos del cliente y filtro por estado | Sesión requerida; rol `CLIENT` |
| `/pedidos/[id]/resena` | Resumen del pedido y formulario de calificación | Sesión requerida; rol `CLIENT` |

Las comprobaciones por rol son apoyo visual. La API mantiene la autorización definitiva. El token no se entrega al cliente: las peticiones autenticadas se ejecutan en servidor con la cookie de sesión existente.

## API utilizada

Las funciones y tipos están en [`lib/api/reviews.ts`](../lib/api/reviews.ts). La única base de URL es `API_URL`, configurada como `/api/v1`.

| Función | Endpoint | Detalle |
|---|---|---|
| `getMyOrders(token, status?)` | `GET /orders/me?status=...` | El filtro solo acepta estados definidos en `ORDER_STATUS_LABELS`. `total` permanece como string y `orderNumber` puede ser `null`; en ese caso se muestra el UUID real. |
| `createReview(token, input)` | `POST /reviews` | Envía `orderId`, `rating` y comentario opcional. Nunca envía `customerId` ni `branchId`. |
| `getBranchRating(branchId)` | `GET /branches/:id/rating` | Público; la sucursal se identifica usando `branchId` del pedido. |

Los estados se presentan mediante el mapa reutilizable `ORDER_STATUS_LABELS`. `ReviewApiError` conserva el status HTTP y el mensaje del servidor, y clasifica 400, 401, 403, 404 y 409.

## Flujo de reseña

1. La tarjeta ofrece **Calificar** únicamente si `status === "DELIVERED"` y `review === null`. Una calificación existente se presenta en modo solo lectura.
2. La ruta de reseña vuelve a consultar `/orders/me` y comprueba la elegibilidad. La Server Action vuelve a validar sesión, rol y estado del pedido.
3. Tras recibir 201, la acción vuelve a consultar pedidos y el promedio de la sucursal; la interfaz refresca el árbol desde servidor y no agrega una reseña optimista.
4. Ante 409, la acción vuelve a consultar pedidos y la interfaz refresca su estado. Se muestra que el pedido ya fue calificado o aún no está entregado.
5. Ante 401 se borra la cookie de sesión y se redirige a `/login`; ante 403 se muestra acceso denegado. Los mensajes 400 y 404 se muestran desde la respuesta de API.

Los datos de pedidos y reseñas no se guardan en storage. `average: null` se presenta como “Sin reseñas”; nunca como cero.

## Componentes

- `RatingStars`: estrellas interactivas con flechas, Home/End y etiquetas accesibles; también tiene modo de solo lectura.
- `ReviewForm`: validación de ayuda, comentario opcional, límite/contador de 500 caracteres y estado de envío.
- La visibilidad de la acción se centraliza en `canRateOrder` dentro de `lib/api/reviews.ts`.
- La lista reutiliza `BadgeEstado`, `EstadoVacio`, `Alerta`, `Button` y `Skeleton`.

## Pruebas y verificación

Ejecutar las pruebas disponibles con Node 24:

```bash
node --experimental-strip-types tests/reviews-api.test.mjs
npm run lint
npm run build
```
