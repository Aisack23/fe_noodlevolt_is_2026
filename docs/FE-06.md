# FE-06 — Tablero de cocina

## Ruta y acceso

La pantalla está disponible en `/cocina/tablero`. El Server Component exige que la sesión exista y que `rol === "COOK"`; cualquier otro rol recibe la plantilla de acceso denegado. Las Server Actions repiten esa comprobación para evitar que la interfaz cliente sea el único control. Una sesión inexistente o una respuesta 401 del backend redirige a `/login` tras borrar la cookie.

El flujo de inicio de sesión de `COOK` ahora dirige a `/cocina/tablero`. No se añade un enlace al sidebar: el diseño aprobado para cocina es un tablero de pantalla completa sin sidebar.

## Contrato integrado

- `GET /kitchen/orders`: obtiene la cola de la sucursal del cocinero con `Authorization: Bearer <token>`.
- `PATCH /kitchen/orders/:id/status`: envía exclusivamente `{ "status": "IN_PREPARATION" | "READY" }`.

`KitchenOrder` valida en tiempo de ejecución el DTO recibido y conserva los nombres técnicos del backend. La UI traduce únicamente los textos de estado para `BadgeEstado`: `PENDING`, `IN_PREPARATION` y `READY` se muestran como Pendiente, En preparación y Listo.

## Estados implementados

El tablero contempla carga mediante skeletons, datos, cola vacía, error de consulta, conflicto de actualización y acción en progreso. El polling consulta la cola cada 5 segundos. Durante una actualización solo se deshabilita la tarjeta afectada, para prevenir envíos duplicados sin bloquear los demás pedidos.

## Referencia visual

Se implementó a partir de `docs/design-assets/Desktop.png` y de los frames documentados `111:1209` (escritorio) y `111:2260` (tableta). Se reutilizan `Button`, `BadgeEstado`, `Alerta`, `EstadoVacio` y `Skeleton`; se añadieron `CocinaTarjetaPedido` y `CocinaLineaPedido` por ser componentes propios del dominio de cocina.
