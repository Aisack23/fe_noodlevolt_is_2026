# FE-03 — Tablero de cocina, listos para entregar y Nueva comanda

## Rutas y acceso

| Ruta | Rol | Uso |
|---|---|---|
| `/cocina/tablero` | COOK | Pedidos pendientes y en preparación (FE-06) |
| `/mesero/listos` | WAITER | Pedidos listos y botón «Entregado» |
| `/mesero/comanda` | WAITER | Nueva comanda en 3 pasos |

Las comprobaciones por rol son apoyo visual. La API mantiene la autorización definitiva (401 sin sesión, 403 rol o sucursal no autorizados). El token vive en una cookie `httpOnly` y solo se usa en el servidor (Server Actions y Server Components).

## Contrato integrado

| Endpoint | Uso | Estado |
|---|---|---|
| `GET /kitchen/orders` | Tablero de cocina | Conectado y probado |
| `PATCH /kitchen/orders/:id/status` | Cocina avanza el pedido (409 si salta una etapa) | Conectado y probado |
| `GET /kitchen/orders/ready` | Pedidos listos del mesero | Conectado y probado |
| `PATCH /kitchen/orders/:id/deliver` | Mesero confirma la entrega | Conectado y probado |
| `GET /branches/:branchId/tables` | Mesas de Nueva comanda | Conectado y probado |
| `GET /sucursales/:id/menu` | Platillos, categorías y nombre de la sucursal | Conectado y probado |
| `POST /orders/salon` | Envío de la comanda (BE-02, solo WAITER) | Conectado y probado: el pedido llega a cocina como «Mesa», con sus notas |

Flujo: componente cliente → Server Action (`actions.ts`) → backend. El tablero y la lista de listos consultan cada 5 s.

## Nueva comanda

La sucursal sale del JWT (`branchId`, expuesto en `SafeSessionUser`). Las mesas se traducen en `lib/api/tables.ts`:

| Backend | Pantalla |
|---|---|
| `AVAILABLE` | Libre (se puede elegir) |
| `OCCUPIED` | Ocupada (se puede elegir) |
| `NEEDS_CLEANING` | Por limpiar (no se puede elegir) |
| `RESERVED`, `OUT_OF_SERVICE` | No se muestran (falta diseño) |

Una mesa en un salón inactivo aparece, pero no se puede elegir.

**Envío del pedido** (`createSalonOrder` en `lib/api/salon.ts`, llamado desde la Server Action `sendSalonOrder`):

- Cuerpo: `tableId`, `operationKey` y `lines` (`dishId`, `quantity` de 1 a 20, `note` de hasta 200 o `null`). La sucursal sale del usuario autenticado; el backend rechaza con 400 cualquier campo extra (por ejemplo `tableNumber`).
- `operationKey` se genera una vez por intento y se reutiliza en reintentos. Cambia cuando cambia el contenido del pedido: el backend responde 409 si la misma clave llega con contenido distinto.
- 201 (creado) y 200 (reintento idéntico) se tratan igual, como éxito.
- 409 por platillo no disponible: el cuerpo trae `dishId` en la raíz. El front marca la línea en rojo, bloquea «Confirmar pedido» y conserva el resto. El backend informa solo el primer platillo no disponible.
- El número que se muestra es `orderNumber` o, si llega `null`, el inicio del `id` en mayúsculas. Es el mismo respaldo que usan el tablero de cocina y `/mesero/listos`.

## Diferencias conscientes con Figma

- Sin «Cuenta abierta» ni su aviso: el backend no informa ese dato por mesa.
- Sin «Marcar limpia»: no existe el endpoint (el módulo de mesas solo tiene `GET`), y ningún flujo actual deja una mesa en «por limpiar». Se necesitará con el cierre de cuenta o el cobro.
- Sin número legible de pedido: el backend no lo genera (`orderNumber` llega `null`).
- El tablero de cocina muestra «Mesa» sin el número: `GET /kitchen/orders` no incluye la mesa.
- «Ver salón» (paso 3) y las demás entradas del menú lateral del mesero (`/mesero/salon`, `cuentas`, `pedidos-llevar`, `documentos-fiscales`) llevan a pantallas que aún no existen (404).
- Las categorías salen del menú real (incluye «Postres»).
- Al quitar un platillo agotado desaparece el aviso rojo.
- El estado de la mesa no cambia al enviar el pedido: el backend no lo modifica, así que la mesa sigue «Libre».

## Pruebas y verificación

Verificado por FE durante el desarrollo; pendiente de validación formal por QA.

- `npx tsc --noEmit`, `npm run lint` y `npm run build`: sin errores. El lint reporta una advertencia que ya venía de `develop` (`app/pedidos/[id]/pago/pago-simulado-client.tsx`).
- Probado en escritorio con el backend real:
  - Cocina avanza un pedido, el mesero lo ve en menos de 5 s y lo entrega.
  - El backend responde 403 al llamar `PATCH /kitchen/orders/:id/status` con un token de WAITER.
  - Nueva comanda: nombre de sucursal, mesas y menú reales; el pedido enviado aparece en el tablero de cocina como «Mesa» y con la nota escrita.
- Pendiente de QA: orden ascendente por fecha de creación en el tablero de cocina (criterio 1) y que un 403 no altere el estado del pedido (criterio 3).
- Sin pruebas automatizadas.
