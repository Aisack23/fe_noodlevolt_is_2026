# FE-07 — Saldo de puntos de lealtad (HU-07)

## Rutas y acceso

| Ruta / componente | Uso | Acceso de interfaz |
|---|---|---|
| `/perfil/puntos` | Saldo disponible y regla de acumulación | Sesión requerida; rol `CLIENT` |
| `SaldoPuntos` (barra del cliente) | Chip «⭐ 1,250 pts» que enlaza a `/perfil/puntos` | Solo se muestra con sesión y rol `CLIENT` |

Las comprobaciones por rol son apoyo visual; la API valida con 401/403. Ante 401 se borra la sesión y se redirige a `/login`; ante 403 se muestra «Acceso denegado».

## API utilizada

| Función | Endpoint | Detalle |
|---|---|---|
| `getMyLoyalty(token)` | `GET /loyalty/me` | Implementado en BE-07. Responde `{ "points": n }`; `0` si el cliente aún no tiene cuenta. Solo se usa `points`. |
| Route handler `GET /api/loyalty/me` | — | Puente para el chip (componente cliente). El token sigue en la cookie httpOnly y nunca llega al navegador, igual que `/api/notifications`. |

El diseño técnico de HU-07 mostraba `{ "userId", "points" }` como ejemplo, pero el contrato implementado en BE-07 devuelve solo `points`.

## Decisiones

- **Sin puntos optimistas.** La pantalla siempre consulta al servidor (`cache: "no-store"`, `dynamic = "force-dynamic"`). El chip vuelve a consultar en cada cambio de ruta, así que al volver de un pago aprobado muestra el saldo acreditado por el backend.
- **Formato:** `1,250 pts`, igual que el diseño acordado (`formatPoints`).
- **Barra móvil:** se cambió el logo de la barra en 360 px a `Logo/Wordmark`, como indica el componente «Navbar cliente» de Figma, para que quepa el chip junto a campana, carrito y avatar.
- **Historial y canje fuera de alcance:** los frames «Mis puntos / Con movimientos» y «Canje» de Figma necesitan endpoints de historial y de canje que no existen en el MVP (BE-07 solo expone el saldo). No se muestran datos inventados.

## Estados (frames de Figma, página E7 Lealtad)

| Estado | Pantalla `/perfil/puntos` | Chip de la barra |
|---|---|---|
| Cargando | `loading.tsx` con skeletons | Bloque skeleton |
| Vacío | `0 pts` + `EstadoVacio` «Aún no tienes puntos» | `0 pts` |
| Éxito | Tarjeta «Saldo disponible» con el saldo y la explicación «Acumula 1 punto por cada $1.00 pagado.» | Saldo |
| Error del servidor | `Alerta` «No se pudo completar la operación. Intenta de nuevo» + botón «Reintentar» | «Sin saldo» (no bloquea la barra) |
| Sin permiso | `AccesoDenegado` | Oculto |

## Pruebas y verificación

```bash
node --experimental-strip-types tests/loyalty-api.test.mjs
npm run lint
npm run build
```

`tests/loyalty-api.test.mjs` simula `fetch` y cubre: header Bearer y `no-store`, saldo 0, campos extra ignorados, 401/403/500 y respuestas con formato inválido, y el formato `1,250 pts`.

Prueba manual de punta a punta: iniciar sesión como cliente → `/perfil/puntos` muestra 0 → pagar un pedido con la tarjeta terminada en **4242** (por ejemplo $12.75 acredita 12 pts) → el saldo sube; pagar con **0002** no cambia el saldo.
