# FE-03 — Tablero de cocina, listos para entregar y Nueva comanda

## Rutas y acceso

| Ruta | Rol | Uso |
|---|---|---|
| `/cocina/tablero` | COOK | Pedidos pendientes y en preparación |
| `/mesero/listos` | WAITER | Pedidos listos y botón «Entregado» |
| `/mesero/comanda` | WAITER | Nueva comanda en 3 pasos (datos de prueba) |

Las comprobaciones por rol son apoyo visual. La API mantiene la autorización definitiva (401 sin sesión, 403 rol o sucursal no autorizados). El token vive en una cookie `httpOnly` y se usa solo en el servidor.

## Contrato integrado (BE-03, PR #36)

- `GET /api/v1/kitchen/orders`: pedidos PENDING e IN_PREPARATION de la sucursal.
- `PATCH /api/v1/kitchen/orders/:id/status`: COOK avanza el estado; 409 si salta una etapa.
- `GET /api/v1/kitchen/orders/ready`: READY de la sucursal del mesero.
- `PATCH /api/v1/kitchen/orders/:id/deliver`: READY → DELIVERED, sin cuerpo.

Flujo: componente cliente → Server Action (`actions.ts`) → backend. Sondeo cada 5 s.

## Nueva comanda: datos de prueba

El backend no tiene endpoints de mesas ni de pedidos de salón. `lib/api/salon.ts` simula `getMesas`, `getSalonMenu`, `markMesaClean` y `createSalonOrder`. Al conectar el backend real solo cambia el contenido de ese archivo.

Supuestos que el backend debería confirmar:
- Mesa: `id`, `number`, `capacity`, `status` (`FREE`, `OCCUPIED`, `TO_CLEAN`), `hasOpenAccount`.
- Crear pedido: mesa, `operationKey`, líneas con `quantity` (1 a 20) y `note` (hasta 200).
- Platillo agotado: 409 con el `dishId`.
- `POST /orders` hoy es solo CLIENTE y su DTO rechaza `note`.

## Diferencias conscientes con Figma

- La sucursal del shell dice «Sucursal asignada»: el JWT no trae el nombre.
- Sin número legible de pedido: el backend no lo genera, y `/mesero/listos` muestra un respaldo con el inicio del id.
- «Ver salón» (paso 3) lleva a `/mesero/salon`, que aún no existe.
- Estados cargando y error del paso 1 y del menú sin validar contra el frame.
- Al quitar un platillo agotado desaparece el aviso rojo.

## Pruebas y verificación

- `npx tsc --noEmit`, `npm run lint` y `npm run build`: confirmar antes del PR.
- Probado en escritorio con backend real: cocina avanza un pedido, el mesero lo ve en menos de 5 s y lo entrega.
