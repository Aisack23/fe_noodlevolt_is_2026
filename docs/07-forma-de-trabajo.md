# Forma de trabajo

- Crea las ramas de cambios a partir de `develop` y abre los PR hacia esa rama.
- Prepara `release/x.y.z` desde `develop` para integrar la versión a `main` una vez aprobada.
- En cada PR incluye la historia, el resumen, cómo probar el cambio y las capturas cuando cambie una pantalla.
- Ejecuta `npm run lint`, `npm test` y `npm run build` antes de pedir revisión.
- Mueve una historia a **Hecho** cuando QA confirme los criterios y la tarjeta tenga el enlace al PR.
